# 安装与运行说明

## 一、环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 1809 (17763) 或更高 / Windows 11，x64 |
| .NET 运行时 | **框架依赖版**需要 .NET 8 Desktop Runtime；**自包含版**不需要 |
| 权限 | 标准模式：普通用户<br>精确模式：**管理员** |
| 磁盘 | 程序 ~3 MB ~ 170 MB（取决于发布方式）；数据目录随日志增长，默认上限 200 MB |

下载 .NET 8 Desktop Runtime：<https://dotnet.microsoft.com/download/dotnet/8.0>（选 "Desktop Runtime"）

---

## 二、从源码编译

```bash
git clone <repo>
cd <repo>

# 编译全部项目
dotnet build CWriteWatcher.sln -c Release

# 跑测试
dotnet test tests/CWriteWatcher.Tests

# 直接运行（调试）
dotnet run --project src/CWriteWatcher.App
```

> 若机器上只有 .NET Runtime 而没有 SDK，需要先装 .NET 8 **SDK**。

---

## 三、发布

提供三种发布形态，按需选择。

### 形态 A：框架依赖（推荐日常使用，默认带真实 Toast）

```bash
dotnet publish src/CWriteWatcher.App -c Release -r win-x64 `
  --self-contained false -o publish/framework-dependent
```

- 体积：**约 26 MB**（其中 24 MB 是真实 Toast 所需的 Windows SDK 投影）
- 需要目标机器已安装 .NET 8 Desktop Runtime
- 优点：能用 `ToastNotificationManagerCompat` 发真正的 Windows Toast 通知

### 形态 B：框架依赖 + 精简（体积优先）

```bash
dotnet publish src/CWriteWatcher.App -c Release -r win-x64 `
  --self-contained false -p:UseRealToast=false -o publish/slim
```

- 体积：**约 2.4 MB**
- 提醒改用 `NotifyIcon.ShowBalloonTip` —— Win10/11 上外壳会把它渲染成系统 Toast 通知
- 需要 .NET 8 Desktop Runtime

### 形态 C：自包含单文件（免安装绿色版）

```bash
dotnet publish src/CWriteWatcher.App -c Release -r win-x64 `
  --self-contained true -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -o publish/self-contained
```

- 体积：**约 165 MB**（含 .NET 运行时）
- 目标机器**无需安装任何运行时**，双击即用
- 加上 `-p:UseRealToast=false` 可降到约 70 MB

### 体积对照

| 形态 | 体积 | 需要运行时 | Toast 实现 |
|---|---|---|---|
| A 框架依赖 | 26 MB | 是 | 真实 Toast API |
| B 框架依赖精简 | 2.4 MB | 是 | 托盘气泡（外壳渲染为 Toast） |
| C 自包含单文件 | 165 MB | 否 | 真实 Toast API |
| C' 自包含精简 | ~70 MB | 否 | 托盘气泡 |

## 四、首次运行

1. 双击 `CWriteWatcher.exe`。
2. **不会弹出任何窗口** —— 程序直接进入系统托盘。
3. 托盘图标右键 → 「打开设置」，或直接双击托盘图标。

### 首次运行建议做的三件事

1. **确认出厂默认配置符合预期**：默认是**模式 B（超过 10 MB）**、标准模式、内置排除表全开。
2. **检查系统通知设置**：Windows 设置 → 系统 → 通知，确认 CWriteWatcher 的通知权限为「开」。
   如果开了「专注助手 / 勿扰模式」，Toast 会被系统静默，此时托盘气泡是兜底通道。
3. **决定是否使用精确模式**（见下）。

---

## 五、切换到精确模式

精确模式能给出**真实的单次写入字节数**和**发起进程**，代价是需要管理员权限。

操作：设置 → 常规 → 选「精确模式」→ 确定。

程序会弹出询问「是否立即以管理员身份重新启动？」：

- **选「是」** → 触发一次 UAC 提权，程序以管理员身份重启，精确模式生效。
- **选「否」** → 保持标准模式，配置不修改。

> 提权只发生在**切换模式的那一刻**。之后如果开启了开机自启，程序会通过
> 「任务计划程序 /RL HIGHEST」在登录时**静默启动，不再弹 UAC**。

### 重启后如果仍是精确模式

程序**每次启动时**都会检查：配置里是精确模式、但当前不是管理员 → 会主动问你是否提权重启。

这是必要的，因为「只在切换模式时提示」不够用：你下次双击启动（或开机自启）时，
配置里已经是精确模式，程序会以普通权限启动、ETW 会话必然失败，
状态页只会显示一句「拒绝访问」，而你并不知道该怎么办。

- 选「是」→ 触发一次 UAC，以管理员身份重启，精确模式正常工作
- 选「否」→ 以普通权限继续启动（托盘可用，但精确模式不工作），可在设置里改回标准模式

### 切回标准模式

设置 → 常规 → 选「标准模式」→ 确定。不需要重启，采集器会就地重启。

### 验证精确模式是否正常工作

托盘右键 → **「导出 ETW 诊断信息」**，会打开一个文本文件，内容包含：

```
是否管理员：是
=== 运行统计 ===
路径映射命中率：98.7%
=== ETW 事件 Schema（用于核对字段布局）===
[ID 12] Create
    FileKey  (InType=16)
    IssuingThreadId  (InType=8)
    ...
[ID 16] Write
    FileKey  (InType=16)
    Offset  (InType=9)
    Size  (InType=10)
    ...
```

如果 `Write` 事件的字段列表里**没有 `Size`**，说明该 Windows 版本的 manifest 与预期不同，
请把这份诊断文件反馈出来。

## 六、开机自启

| 模式 | 自启位置 | 是否需要管理员 |
|---|---|---|
| 标准模式 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` | 否 |
| 精确模式 | 任务计划程序 `CWriteWatcher`，`/SC ONLOGON /RL HIGHEST` | 创建任务需要一次管理员授权 |

**为什么精确模式不用 Run 键**：精确模式需要管理员，用 Run 键启动会**每次开机都弹 UAC**，体验灾难。
任务计划以最高权限运行则登录时静默启动、不弹 UAC。

**切换模式时会自动清理另一种模式遗留的自启项**（先无条件删除两个位置，再写目标位置）。
如果不这样做，两个自启项会同时存在 → 开机启动两次 → 第二个实例虽然会被单实例锁挡住，
**但 UAC 提示已经弹出来了**。

### 手动清理

如果自启项残留：

```cmd
reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v CWriteWatcher /f
schtasks /Delete /TN CWriteWatcher /F
```

## 七、配置与数据位置

```
%AppData%\CWriteWatcher\
  config.json          # 全部配置
  events.db            # SQLite 日志（WAL 模式）
  events.db-wal
  events.db-shm
  diagnostics-*.txt    # 手动导出的诊断信息
```

打开方式：托盘右键 → 「打开配置目录」，或设置 → 日志 → 「打开数据目录」。

### 配置损坏时

程序启动时若无法解析 `config.json`，会把原文件重命名为
`config.json.corrupt-<yyyyMMddHHmmss>` 并回退到默认配置，不会静默丢数据。

### 恢复默认

设置 → 排除表 → 「恢复默认排除表」只重置排除表。
要整体重置，直接删除 `config.json` 后重启程序。

## 八、卸载

1. 托盘右键 → 退出。
   > 程序退出时会检查：如果配置里自启已关闭但注册表/计划任务里还有残留，会自动清理。
2. 删除程序目录。
3. 删除 `%AppData%\CWriteWatcher\`。

若开启了自启，建议退出前先在设置里关掉「开机自动启动」。

## 九、常见问题

**Q：托盘没有图标？**
Windows 11 默认折叠新图标。点任务栏的 `^` 展开，把图标拖到任务栏常驻区。
也可以在设置 → 个性化 → 任务栏 → 其他系统托盘图标里打开。

**Q：完全不提醒？**
按顺序排查：
1. 设置 → 状态，看「接收事件」是否在增长。如果一直是 0，说明采集器没工作。
2. 看「低于阈值」计数。模式 B 只对累计超过 10 MB 的写入提醒，小文件不会触发。
3. 看「静默抑制」/「节流抑制」/「降级丢弃」计数。
4. 看「治理级别」是不是 L2/L3 —— 系统负载高时程序会主动降级。
5. 检查系统是否开了「专注助手 / 勿扰模式」。

**Q：托盘图标变红了，但没有弹窗？**

图标变红说明**程序确实产生了提醒**（`AlertNotified` 已触发），问题在通知通道。
先点 **设置 → 提醒 → 「发送测试提醒」**，它会走与真实提醒完全相同的代码路径，
并在按钮下方直接显示每个通道的实际结果：

| 自检结果 | 含义 | 怎么办 |
|---|---|---|
| `置顶窗 ✓`，但看不到卡片 | 几乎不可能 —— 自绘窗口不经过系统通知 | 检查是否被其他全屏窗口挡住 |
| `置顶窗 ✗` | 自绘通道本身出错 | 把「通道错误」那一行发出来 |
| `Toast ✗ / 气泡 ✗`，但 `置顶窗 ✓` | **系统把通知静默了** | 见下面「两个开关」 |
| 全部 `✗` | 通道本身有问题 | 把「通道错误」那一行发出来 |

**最重要的两个开关**（这两个是 Win10/11 上最常见的静默原因）：

1. **通知总开关** —— 设置 → 系统 → 通知 → 最上面的「通知」开关。
   对应注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\PushNotifications\ToastEnabled`，
   为 `0` 时**所有应用**的 Toast 都被丢弃（本项目实际遇到过）。
2. **专注助手 / 勿扰模式** —— 设置 → 系统 → 专注助手。它只抑制横幅，不丢弃通知。

> ⚠️ **Toast 和托盘气泡走的是同一条 Windows 通知管道。**
> Win10/11 上 `ShowBalloonTip` 也是由外壳渲染成 Toast 的，
> 所以上面任一开关生效时，**两条会一起失效，而且 API 完全不报错**。
>
> **「自绘置顶提示窗」不受影响** —— 它是程序自己画的顶层窗口。
> 默认开启，建议保持开启。想再加一道保险可以打开「声音提示」（走 `SystemSounds`，同样绕开通知平台）。

**Q：怎么确认提醒到底发出去了几次？**

两个地方都有：
- **设置 → 状态**：「提醒通道」「已发送」「通道错误」三行（含置顶窗 / Toast / 气泡 / 声音各自计数）。
- **右键托盘 → 导出 ETW 诊断信息**：文件里有 `=== 提醒通道 ===` 一段。

「已发送」有计数但屏幕上没出现 → 就是被系统静默了，不是程序的问题。

**Q：自绘置顶提示窗是什么？**

右下角的一张卡片，显示时间、文件路径、写入大小、进程名、触发模式。
- **不经过 Windows 通知平台**，任何系统通知设置都挡不住；
- 不抢焦点（`WS_EX_NOACTIVATE`）、不占任务栏、不进 Alt-Tab；
- **鼠标悬停暂停倒计时**（方便看清长路径），**单击卡片打开日志窗口**，点右上角 `×` 关闭；
- 显示时长在 设置 → 提醒 → 显示 N 秒 可调（默认 8 秒）。

**Q：提示"已在运行"但找不到窗口？**
如果已运行的实例是**管理员权限**，普通权限的本次启动无法唤起它的窗口 ——
这是 Windows 的 UIPI（用户界面特权隔离）限制，无法绕过。请到系统托盘里找。

**Q：CPU 占用偏高？**
设置 → 状态看「治理级别」和「事件速率」。如果是 L2/L3，程序已经在自动降级保护系统了。
可以进一步在排除表里关闭一些不需要的规则，或缩小监控范围。

**Q：精确模式下很多事件显示"未知路径"？**
这是预期行为。程序**启动之前**就已打开的长期句柄（数据库、日志、正在下载的大文件）
永远拿不到 `Create` 事件，因此无法建立 `FileKey → 路径` 映射。
建议开机后尽早启动本工具以提高映射命中率。设置 → 状态里的「路径映射命中率」反映这个比例。

**Q：标准模式下"写入大小"显示为 `≈ 12.4 MB`？**
标准模式拿不到真实的单次写入字节数，只能靠文件大小差分估算，因此显示 `≈`。
需要精确值请切换到精确模式。
